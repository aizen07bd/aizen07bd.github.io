# 균열 방어선 개발기 5편: 현재 버전의 한계와 다음 업데이트 방향

> 이 글은 무료 웹 디펜스 게임 **균열 방어선** 개발기 마지막 글입니다.  
> 이번 편에서는 현재 버전의 아쉬운 점과 다음 버전에서 개선하고 싶은 내용을 정리합니다.

## 시작하며

균열 방어선을 무료 웹게임으로 공개하면서 가장 중요하게 생각한 것은 "일단 끝까지 플레이 가능한 형태를 만든다"는 것이었습니다.

현재 버전에는 시작 화면, 인트로, 캐릭터 선택, 10개 맵, 50개 스테이지, 자동 전투, 보상 카드, 캐릭터 스킬, 동료 합류 컷씬, 엔딩까지 들어 있습니다. 하나의 게임 흐름은 갖췄다고 볼 수 있습니다.

하지만 실제로 플레이해보면 개선할 부분도 분명히 보입니다. 이번 글에서는 그 부분을 숨기기보다, 다음 버전에서 어떤 방향으로 다듬고 싶은지 정리해보려고 합니다.

## 현재 버전에서 만족스러운 점

먼저 좋았던 점부터 정리해보면, 가장 큰 성과는 웹에서 바로 플레이 가능한 형태로 게임을 완성했다는 것입니다.

링크 하나로 공유할 수 있고, 모바일 브라우저에서 바로 실행할 수 있습니다. 별도 설치가 필요 없기 때문에 피드백을 받기도 쉽습니다.

게임 구조도 처음 목표와 크게 어긋나지 않았습니다.

- 세로 화면에서 적이 내려오는 압박감
- 바리케이드를 지키는 명확한 목표
- 자동 전투로 줄인 조작 부담
- 보상 카드로 남긴 선택의 재미
- 판타지와 현대를 오가는 진행감
- 캐릭터가 하나씩 합류하는 파티 완성감

프로토타입으로는 핵심 방향을 확인할 수 있었습니다.

## 아쉬운 점 1: 밸런스 조정

가장 먼저 손봐야 할 부분은 밸런스입니다.

현재는 스테이지가 올라갈수록 몬스터 수와 속도, 체력이 증가합니다. 캐릭터는 보상 카드와 스킬 해금을 통해 강해집니다. 기본 구조는 맞지만, 세부 수치는 더 다듬을 필요가 있습니다.

특히 다음 부분을 확인해야 합니다.

- 초반 난이도가 너무 쉽거나 어렵지 않은가
- 특정 카드만 지나치게 강하지 않은가
- 스킬 해금 카드가 기본 강화 카드보다 항상 좋은 선택이 되는가
- 바리케이드 회복 카드의 가치가 적절한가
- 후반 스테이지에서 전투가 너무 길어지지 않는가

밸런스는 코드만 보고 맞추기 어렵습니다. 실제 플레이 데이터와 피드백이 필요합니다. 다음 버전에서는 스테이지별 클리어율, 평균 선택 카드, 게임 오버 지점 같은 정보를 확인할 수 있는 방법도 고민하고 있습니다.

## 아쉬운 점 2: 저장 기능

현재 버전에서 가장 크게 느껴지는 불편함은 저장 기능입니다.

전체 루트는 50스테이지입니다. 끝까지 한 번에 플레이할 수도 있지만, 모바일 웹게임이라는 특성을 생각하면 중간 저장이 있는 편이 훨씬 좋습니다.

다음 버전에서는 최소한 다음 정보는 저장하고 싶습니다.

- 현재 스테이지
- 선택한 시작 캐릭터
- 합류한 동료
- 해금된 스킬
- 누적 보상 카드 효과
- 바리케이드 최대 체력
- 점수

처음에는 서버 저장까지 가지 않고, 브라우저의 로컬 저장소를 사용하는 방식으로 시작해도 충분할 것 같습니다. 웹게임의 장점을 유지하면서도 플레이를 이어갈 수 있게 만드는 것이 목표입니다.

## 아쉬운 점 3: 반복 플레이 동기

현재 구조는 한 번 끝까지 플레이하는 데 초점이 맞춰져 있습니다. 하지만 다시 플레이할 이유는 아직 부족합니다.

시작 캐릭터에 따라 루트가 달라지기는 하지만, 보상 카드 풀과 전체 전투 흐름은 큰 틀에서 같습니다. 장기적으로는 반복 플레이를 유도할 장치가 필요합니다.

생각 중인 방향은 다음과 같습니다.

- 캐릭터별 클리어 기록
- 난이도별 클리어 배지
- 맵별 최고 점수
- 랜덤 보상 카드 확장
- 캐릭터별 고유 강화
- 도전 모드

이 중 가장 현실적인 것은 캐릭터별 클리어 기록과 난이도 선택입니다. 구현 범위가 크지 않으면서도 다시 시작할 이유를 줄 수 있습니다.

## 아쉬운 점 4: 카드 종류 부족

현재 보상 카드는 기본적인 성장 방향을 제공합니다. 화력, 공격 속도, 관통, 둔화, 폭발, 회복, 최대 체력 같은 요소입니다.

하지만 오래 플레이할수록 선택지가 익숙해집니다. 다음 버전에서는 카드 종류를 늘리고, 카드 간 조합이 생기도록 만들고 싶습니다.

예를 들어 이런 카드가 가능합니다.

| 카드 방향 | 예시 효과 |
| --- | --- |
| 캐릭터 강화 | 특정 캐릭터의 공격 속도 증가 |
| 스킬 강화 | 특정 스킬의 쿨타임 감소 |
| 조건부 강화 | 바리케이드 HP가 낮을 때 피해 증가 |
| 속성 강화 | 둔화된 적에게 추가 피해 |
| 생존 강화 | 바리케이드가 처음 파괴될 때 1회 복구 |
| 선택형 강화 | 공격력 증가 대신 최대 HP 감소 |

특히 캐릭터별 전용 카드가 들어가면 파티 성장의 개성이 살아날 것 같습니다. 마법사는 메테오 강화, 여학생은 레이저 지속 시간 증가, 남학생은 공중지원 폭격 횟수 증가처럼 캐릭터 정체성과 연결되는 카드가 있으면 좋겠습니다.

## 아쉬운 점 5: 맵별 차별화

현재 맵은 배경, 적 이미지, 보스 이미지가 다릅니다. 하지만 규칙 자체는 거의 동일합니다.

다음 버전에서는 맵마다 작은 특수 규칙을 넣어보고 싶습니다.

예를 들어 다음과 같은 방식입니다.

- 사막: 일정 시간마다 시야를 가리는 모래바람
- 정글: 몬스터 일부가 둔화 저항을 가짐
- 추운지방: 아군 공격 속도가 일시적으로 느려짐
- 용암던전: 바리케이드가 주기적으로 추가 피해를 받음
- 학교: 빠른 좀비가 더 자주 등장
- 한강: 중간 보스가 여러 번 등장

맵별 규칙은 너무 복잡하면 오히려 피로해질 수 있습니다. 그래서 한 맵에 하나의 특징만 넣는 정도가 적절해 보입니다.

## 아쉬운 점 6: UI와 모바일 사용성

현재 UI는 기능 중심으로 구성되어 있습니다. 플레이는 가능하지만, 더 다듬을 여지가 많습니다.

특히 모바일에서는 다음 부분을 개선하고 싶습니다.

- 보상 카드 터치 영역 개선
- 전투 중 스킬 준비 상태 표시 강화
- 바리케이드 HP 경고 연출
- 게임 오버 후 재시작 흐름 개선
- 캐릭터 선택 화면의 정보량 조정
- 작은 화면에서 텍스트 가독성 확인

자동 전투 게임에서는 UI가 곧 조작감입니다. 직접 버튼을 누르는 액션이 적기 때문에, 현재 상황을 얼마나 잘 보여주는지가 중요합니다.

현재 프로토타입은 빠르게 완성하는 것을 우선했습니다. 그래서 많은 로직이 하나의 메인 파일에 들어 있습니다.

분리하고 싶은 영역은 다음과 같습니다.

- 캐릭터 데이터
- 스킬 데이터
- 보상 카드 데이터
- 전투 씬
- 컷씬 처리
- 사운드 처리
- 저장/로드 처리

처음부터 큰 구조를 만들었다면 개발 속도가 느려졌을 수 있습니다. 하지만 이제 기본 게임 루프가 확인되었기 때문에, 다음 단계에서는 유지보수하기 좋은 구조로 나누는 작업이 필요합니다.

그 다음은 밸런스입니다. 저장이 생기면 더 긴 플레이가 가능해지고, 그만큼 후반 밸런스의 문제가 더 잘 드러날 것입니다.
