# 4편. 보안 게임을 미연시처럼 보이게 만든 이유 - 디자인 설계

`Hacker Life: Trace`는 보안 분석을 다루지만, 화면을 차갑고 딱딱한 대시보드로만 채우고 싶지는 않았다. 이 게임은 성장 드라마이기도 하다. 주인공은 동기, 선배, 친구, 기자, 회사 인턴, 보안팀 직원과 만나며 사건을 해결한다. 그래서 화면 구성은 일반적인 보안 훈련 플랫폼보다 비주얼 노벨에 가깝게 잡았다.

대화로 사건을 받아들이고, 조사 화면에서 흔적을 확인하고, 다시 대화로 판단을 검증하는 구조다. 이 흐름을 자연스럽게 만들기 위해 시각 디자인도 크게 세 가지 축으로 나눴다.

1. 실사풍 캐릭터와 배경
2. 글래스모피즘 기반 모바일 UI
3. 4컷 만화식 컷씬과 패널 모션

## 실사풍 캐릭터를 선택한 이유

초기에는 만화풍 캐릭터도 생각할 수 있었다. 하지만 이 게임의 주제는 실제 보안 사고에 가깝다. 피싱 문자, 공용 PC 세션, 웹 서버 로그, EDR 이벤트, 포렌식, 악성코드 분석은 모두 현실에서 볼 수 있는 소재다. 그래서 캐릭터도 너무 과장된 애니메이션 스타일보다 실사풍이 더 잘 어울렸다.

실사풍 캐릭터는 사건의 무게를 살리는 데 좋다. 한민서가 불안한 표정으로 “잠깐만 봐줄 수 있어?”라고 말할 때, 부모님이 피싱 문자 때문에 당황할 때, 보안팀장이 공식 절차를 설명할 때 현실감이 생긴다.

물론 모든 장면을 완전한 실사 영화처럼 만들지는 않았다. 게임은 여전히 대화창, 캐릭터 등장/퇴장, 컷씬 전환을 가진다. 현실적인 소재와 게임적인 연출 사이의 균형을 잡는 것이 목표였다.

## 인물 배치: 한 명이면 중앙, 여러 명이면 좌우

대화 장면에서 캐릭터 배치는 생각보다 중요했다. 처음에는 한민서를 오른쪽에 크게 배치했는데, 모바일 화면에서는 인물이 너무 꽉 차 보였다. 그래서 한 명만 등장하는 장면에서는 중앙 배치를 기본으로 잡았다. 무릎 부근이 하단 대화창과 자연스럽게 겹치도록 조정하면, 모바일 화면에서도 안정적인 구도가 나온다.

등장인물이 둘 이상일 때는 좌우 배치를 사용한다. 한 명이 먼저 들어오고, 퇴장하지 않은 상태에서 다른 인물이 들어와 두 명이 대화한다. 이후 한 명이 나가고 다른 인물이 그 자리에 들어오는 방식이다. 이 방식은 에피소드 3, 8, 9, 11 이후처럼 등장인물이 많은 장면에서 특히 중요하다.

보안 분석 게임은 자칫 혼자 로그만 보는 게임이 되기 쉽다. 인물 배치는 사건이 팀 단위로 진행되고 있다는 느낌을 준다.

## 글래스모피즘 UI

게임의 UI는 어두운 배경 위에 반투명한 유리 질감의 패널을 얹는 방향으로 잡았다. 대화창, 상단 에피소드 라벨, 버튼, 증거 카드, 결과 화면 모두 같은 계열의 질감을 사용한다.

이 선택에는 두 가지 이유가 있다.

첫째, 실사풍 배경과 잘 어울린다. 완전히 불투명한 UI 박스를 올리면 배경과 캐릭터가 끊겨 보인다. 반투명 패널은 장면의 분위기를 유지하면서도 글자를 읽을 수 있게 해준다.

둘째, 보안/추리 장르의 차분한 분위기를 만든다. 네온 사이버펑크처럼 과하게 화려한 UI가 아니라, 어두운 화면 위에 얇은 테두리와 흐릿한 빛을 얹어 분석 도구 같은 느낌을 준다.

다만 글래스모피즘은 주의가 필요하다. 글씨가 배경에 묻히면 안 된다. 그래서 대화창은 충분한 어두운 배경과 테두리를 두고, 본문 글자는 굵게 처리했다. 모바일 화면에서는 글자 크기도 과하면 답답해지므로 여러 차례 조정했다.

## 상단 설명창은 기본 숨김으로 바꿨다

중간 개발 과정에서 상단에 독백/힌트 설명창을 띄우는 장면이 있었다. 처음에는 분위기를 살리는 장치처럼 보였지만, 실제 플레이 화면에서는 캐릭터 얼굴을 가리는 문제가 있었다. 특히 등장인물이 많은 에피소드에서는 상단 설명창이 오히려 몰입을 방해했다.

그래서 이후에는 기본적으로 숨기고, 오른쪽 힌트 버튼을 눌렀을 때만 나타나게 수정했다. 힌트는 필요할 때만 꺼내 보는 보조 정보가 되어야지, 모든 장면을 덮는 UI가 되어서는 안 된다는 판단이었다.

## 4컷 만화식 컷씬

이 게임의 중요한 시각 장치 중 하나가 4컷 만화식 컷씬이다. 각 에피소드의 프롤로그와 에필로그는 대각선 경계로 나뉜 4개의 장면으로 구성된다. 프롤로그는 사건의 시작을 압축해서 보여주고, 에필로그는 분석 결과나 다음 사건으로 이어지는 단서를 보여준다.

이 컷씬은 단순 이미지 한 장으로 끝나지 않는다. 패널이 좌우에서 날아와 퍼즐처럼 맞춰지는 애니메이션을 넣었다. 프롤로그에서 사용한 이 방식은 이후 사건 재구성 장면에도 반복된다. 플레이어는 대화와 조사 사이에서 “지금부터 한 사건이 시작된다”는 느낌을 받는다.

처음에는 텍스트를 컷 안에 크게 넣는 시도도 있었다. 하지만 텍스트가 인물 얼굴을 가리거나, 장면 자체의 힘을 줄이는 문제가 생겼다. 그래서 컷씬의 목적에 따라 텍스트를 줄이고, 그림만으로 흐름을 이해할 수 있게 하는 방향을 선택했다.

## 조사 화면의 구도

모바일 조사 화면은 항상 공간이 부족하다. PC판이라면 브라우저, 터미널, 로그 뷰어를 크게 보여줄 수 있지만, 모바일에서는 그렇게 하면 버튼과 설명을 놓을 곳이 없다.

그래서 조사 화면은 대체로 다음 구도를 따른다.

- 상단: 현재 조사 중인 시스템이나 상황을 보여주는 이미지
- 중단: “어디부터 확인해볼까?” 같은 짧은 질문
- 하단: 조사 항목 버튼
- 측면: 증거 카드와 힌트 버튼
- 하단 고정 영역: 증거 카드 보기, 조사 완료

이 구도는 에피소드 1의 LMS 화면에서 시작해 에피소드 14의 악성코드 분석 도구 선택까지 이어진다. 상단 이미지는 분위기와 맥락을 만들고, 버튼은 실제 조사 흐름을 만든다.

## 증거 이미지는 왜 실사형으로 만들었나

중간에 SVG 기반의 로그 화면도 만들었다. 하지만 사용자가 보기에는 너무 깨끗하고 인위적이었다. 실제 분석 화면은 완벽한 카드처럼 정리되어 있지 않다. 모니터, 노트북, 휴대폰, 보안장비 대시보드, 포렌식 도구 화면처럼 조금은 현실적인 맥락이 있어야 한다.

그래서 에피소드 3 이후부터는 가능한 한 증거와 함정 이미지를 실사형 화면으로 만들었다. 카페의 노트북 화면, 회사 보안실의 모니터, FTK Imager 분석 화면, IDA Pro와 Ghidra 같은 도구 화면이 등장한다.

실사형 증거 이미지는 몰입감을 높인다. 플레이어는 “문제 카드”를 보는 것이 아니라, 실제 현장에서 화면을 들여다보는 느낌을 받는다.

## 성공/실패 스탬프

결과 화면도 처음에는 단순히 성공/실패 문구만 보여줬다. 하지만 이펙트가 약했다. 그래서 화면 중앙에 기울어진 도장 형태의 `SUCCESS`, `FAILED` 이미지를 찍는 효과를 넣었다. 몇 초 뒤 사라지는 방식이라 결과 판정의 리듬을 만든다.

이 작은 효과는 생각보다 중요했다. 플레이어는 자신이 제출한 결론이 판정되는 순간을 더 강하게 느낀다. 보안 분석 게임이라고 해서 모든 피드백이 건조할 필요는 없다.

## 색과 분위기

전체 색감은 어두운 배경, 청록색 포인트, 흰색 본문, 붉은 실패/경고, 초록색 성공 계열로 잡았다. 보안 장르에서 흔히 쓰이는 파란색과 청록색을 사용하되, 화면 전체가 한 가지 색으로만 읽히지 않도록 실사 배경의 톤을 섞었다.

에피소드마다 배경은 다르다. 강의실, 집, 동아리방, 컨퍼런스, 카페, 회사 보안실, 분석실이 등장한다. 하지만 UI 톤은 유지된다. 장면은 바뀌어도 게임의 정체성은 유지되도록 한 것이다.

## 모바일 우선 디자인의 한계와 선택

모바일판은 접근성이 좋지만, 기술 표현에는 한계가 있다. 터미널 명령어 입력, 복잡한 로그 라인 선택, 긴 보고서 작성 같은 기능은 모바일에서 부담스럽다. 그래서 모바일판은 `조사 항목 선택`, `증거 이미지 확인`, `증거 기록`, `결론 제출`을 중심으로 설계했다.

반대로 PC판에서는 더 깊은 입력형 분석을 넣을 수 있다. 실제 명령어 입력, 윈도우식 화면 조작, 터미널 기반 조사, 더 긴 로그 비교 등이 가능하다. 그래서 현재 모바일 버전은 시즌 1의 접근성 좋은 버전이고, 향후 PC판은 더 깊은 분석 모드로 확장할 수 있다.

## 마무리

`Hacker Life: Trace`의 디자인은 보안 분석과 비주얼 노벨 사이의 균형을 찾는 과정이었다. 너무 교육 플랫폼처럼 보이면 드라마가 죽고, 너무 연애 시뮬레이션처럼 보이면 보안 분석의 무게가 사라진다.

그래서 실사풍 인물, 글래스모피즘 UI, 4컷 만화식 컷씬, 실사형 증거 이미지라는 조합을 선택했다. 목표는 하나다. 플레이어가 사건 속에 들어와 있다는 느낌을 받으면서도, 보안 분석가처럼 판단하게 만드는 것.
